The Fragility of Internal Encryption

Why legacy enterprise PKI practices cause critical outages and security blindspots.

Legacy Approaches

  • The 5-Year Time Bomb: Teams issue long-lived certificates that are forgotten until they expire at 3 AM on a weekend, taking down entire pipelines.
  • OpenSSL Complexity: Multi-step manual key generation and CSR signing with zero auditability or centralized revocation.
  • Browser Warning Fatigue: Internal services display red certificate error screens; developers learn to ignore security boundaries.
  • SSH Key Sprawl: Unrevoked public keys persist in authorized_keys files long after employees leave.

Why Public CAs Cannot Solve This

  • No Private Network Scope: Let's Encrypt cannot validate private addresses (localhost, 10.0.0.x, db.internal).
  • Public Leakage: Public certificates are published to Certificate Transparency logs, exposing internal hostnames.
  • External Dependency: Private infrastructure cannot depend on third-party internet uptime to sign internal certificates.

Request Lifecycle & Identity Verification

How requests transition from raw identity proofs into cryptographically signed credentials.

Tier Component Operational Responsibility
1. Client step CLI, Certbot, Microservice SDK Requests certificate issuance, renewal, or revocation over HTTPS/mTLS.
2. Provisioner OIDC, ACME, JWK, AWS/GCP, SCEP, Webhook Authentication Gate: Validates calling identity (human SSO token, cloud instance metadata, or cryptographic JWK).
3. Policy Engine X.509 Templates & Subject Rules Enforces allowed Subject Alternative Names (SANs), extensions, key usages, and validity durations.
4. Signing Core CAS (SoftCAS, Vault, Cloud KMS) Cryptographically signs the certificate using the Intermediate CA key and records serials in the local database.

Passive Revocation vs. Broken Revocation Lists

Why 24-hour certificate lifetimes outperform legacy CRL and OCSP mechanisms.

The Failure of CRL & OCSP

  • Certificate Revocation Lists (CRLs): Bulky lists of revoked serial numbers downloaded periodically. High bandwidth overhead; rarely fresh.
  • OCSP Responders: Checks certificate status on every TLS handshake. If the OCSP server drops, HTTPS handshakes fail or browsers 'soft-fail' and ignore it.
  • The Reality: In real production networks, most clients skip revocation verification entirely.

The step-ca Paradigm: Passive Revocation

  • Short-Lived by Default: TLS certificates are issued for 16 to 24 hours only.
  • Automated Background Renewal: Connected clients renew credentials halfway through their lifetime without service restarts.
  • Clean Revocation: If a host is terminated or a key is leaked, renewals cease. The credential self-invalidates within hours.

Application Consumption: Node.js HTTPS

Wiring localhost.crt and localhost.key directly into an Express server.

const https = require('https');
const fs = require('fs');
const express = require('express');

const app = express();
app.get('/', (req, res) => res.send('Secure Hello World!'));

// Load X.509 credentials issued by step-ca
const options = {
  key: fs.readFileSync('localhost.key'),
  cert: fs.readFileSync('localhost.crt')
};

// Bind encrypted TLS socket on port 3000
https.createServer(options, app).listen(3000, () => {
  console.log('HTTPS server running at https://localhost:3000');
});
